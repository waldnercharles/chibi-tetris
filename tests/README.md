# Focused authored checks

Build from the game root with `make -f tests/Makefile test-build ENGINE=/path/to/pinned/chibi`, then run `make -f tests/Makefile test ENGINE=/path/to/pinned/chibi CTL=/path/to/chibi_ctl`. The engine's production test supervisor applies its 60-second ceiling. The single C/pico_unit dispatcher also enforces one 58-second deadline for all runtime checks and kills its active controller process group on timeout. Build timing is separate. For diagnosis, the binary accepts `--all /path/to/chibi_ctl /path/to/game` or the `STILLWATER_CTL` and `STILLWATER_PROJECT` environment variables.

The dispatcher clones the authored content with copy-on-write into a fresh `/tmp/stillwater-tests-*` directory and adds the small fixtures in this directory. It does not modify the game project. Successful runs remove that directory. Failed runs print its path and retain the last request and response for diagnosis.

The rules fixture calls the live `Pieces` and `Rules` libraries. Board fixtures use the actual `Board` prototype and authored input map, driven through keyboard and two-slot controller input timelines. They check deterministic bags, geometry, SRS floor and wall kicks, collision, ghost placement, row compaction, spin scoring, combos, back-to-back awards, hold limits, auto-repeat, dropping, pause, restart, lock-reset limits, top-out, rescue, the fixed entity pool, and successful-action feedback serials with world-space drop positions.

Shell fixtures run the actual `World` prototype and `Shell` behavior. Test-only board telemetry supplies clear counts and top-outs to exercise direct Journey launch, chapter unlocks and restarts, Sprint completion, Duet reserves, rescue and failure, controller-disconnect pause, keyboard preference changes and save commits. Real 7 / 8 key inputs select unlocked chapters while paused or after a result, stop at unlock bounds and leave active play alone. A second fresh runtime receives the first runtime's exported `saved_state` and verifies settings and chapter reopening. These isolated snapshots never access the player's save file; the SDK's storage tests cover filesystem transport. Browser storage was checked through save/reload in the real player, as recorded in `docs/validation.md`.

The unowned EnvStream prototype first runs by itself and must emit no particles before its owner configures it. The production Stillwater scene also runs directly. Its check exercises drop, pause/resume and mode keys, verifies that the UI snapshot is empty, observes native particles, and confirms that effects-off and reduced-motion settings suppress particles while gameplay remains active. Mode changes retain the same entity pool.

A small 3D scene runs the same production World and Hud with test boards so the snapshot includes every mesh label. The Sprint display check inspects the visible mesh digits and punctuation. It verifies a restored best time of 2:03.4, elapsed-time digits, a clock that remains stopped throughout pause, the missing-best label for a new profile, and chapter keys that do not change Sprint mode.

These are bounded simulation checks. They do not claim GPU rendering, physical-controller input, audio output, browser playability, or full engine-suite coverage.
